# Ледокол

Сервис, который по банковской выписке малого бизнеса строит прогноз остатка на месяц вперёд и заранее говорит, когда денег может не хватить: какого числа, сколько и из-за каких платежей. Плюс подсказывает, что с этим сделать — перенести платёж, напомнить клиенту об оплате или взять овердрафт.

Делаем на хакатон «Центр-инвест» (осень 2026), кейс «Сервис финансового прогнозирования для малого бизнеса».

## Что уже работает

- ручной ввод проведённых платежей, загрузка CSV, TXT 1С-клиент-банк и текстовых PDF Райффайзенбанка;
- регистрация с подтверждением email и повторной отправкой письма;
- категоризация операций: правила → история контрагента → ML для незнакомых формулировок;
- поиск регулярных платежей (аренда, зарплата аванс + расчёт, кредиты, подписки) и налоговый календарь 2026;
- прогноз остатка на 30 рабочих дней с коридором «обычного разброса» и вероятностью нехватки;
- предупреждения о разрывах с причинами и вариантами действий;
- ручной ввод ожидаемых платежей («клиент обещал 300 тыс. 20-го») — прогноз пересчитывается сразу;
- сценарии «что если»: клиент заплатит позже, выручка упадёт, внеплановый расход, рост постоянных расходов;
- план-факт по ожидаемым платежам;
- синхронизация счетов из 1С и проверка контрагентов в ФНС — через отдельные сервисы-имитаторы;
- пакетный прогноз по папке выписок и бэктест с метриками.

## Структура

```
backend/     FastAPI + pandas, вся логика прогноза в app/domain
frontend/    Vue 3 + Vite + TypeScript
mocks/       имитаторы 1С (OData) и ФНС (REST)
analytics/   разведочный анализ датасета: ноутбук и HTML-отчёт
docs/        ТЗ, экраны фронта, план работ, налоговые сроки
```

Подробно, что где лежит и что делать дальше, — в [docs/DEVELOPER_TZ.md](docs/DEVELOPER_TZ.md). Экраны и кнопки — в [docs/frontend_screens.md](docs/frontend_screens.md).

## Запуск

Нужны [uv](https://docs.astral.sh/uv/) и Node.js 22. Датасет кейса кладём в `data/statements/` (в репозиторий он не попадает).

Бэкенд:

```bash
cd backend
uv sync
cp .env.example .env    # заполнить CASHFLOW_JWT_SECRET и CASHFLOW_DEMO_PASSWORD
uv run cashflow seed-demo --input ../data/statements --companies C009,C066,C082,C111 --cutoff 2026-09-18
uv run uvicorn app.main:app --port 8000
```

Фронт:

```bash
cd frontend
npm install
npm run dev
```

Дальше открываем http://127.0.0.1:5173 и входим под `demo` с паролем из `.env`.

Имитаторы 1С и ФНС (если нужны интеграции):

```bash
cd mocks
MOCK_DATA_DIR=../data/statements MOCK_TOKEN=dev-mock-token uvicorn onec_mock:app --port 8101
MOCK_TOKEN=dev-mock-token uvicorn fns_mock:app --port 8102
```

Через Docker:

```bash
docker compose up --build
```

Регистрация доступна со страницы входа. Локальные письма открываются в Mailpit на http://localhost:8025.
Подключение реального SMTP, поддерживаемые выписки и образцы описаны в [инструкции](docs/payments-and-registration.md).

## Прогноз по папке выписок

```bash
cd backend
uv run cashflow predict --input ../data/statements --out results
```

На выходе `forecast.csv` (P10 / P50 / P90 по дням) и `alerts.csv` (разрывы с объяснением). Если на какой-то компании что-то пошло не так, она уйдёт в `errors.csv`, остальные досчитаются.

## Качество

```bash
uv run cashflow backtest --input ../data/statements --out backtest
uv run pytest
```

Бэктест — скользящее окно, 4 отсечки на компанию, горизонт 30 рабочих дней, 20% компаний отложены как «контрольные». Текущие цифры:

| | обычные | отложенные |
|---|---|---|
| найдено разрывов (recall) | 0,68 | 0,55 |
| точность предупреждений | 0,55 | 0,58 |
| за сколько рабочих дней предупреждаем (медиана) | 13 | 9 |

На горизонте 5–10 дней прогноз остатка точнее наивного, на 20–30 днях пока нет — это следующая задача.

## LLM

Необязательный ассистент «спроси о своих деньгах» работает через любой OpenAI-совместимый API (ключ и модель — в `.env`, по умолчанию выключен). В модель уходят только обезличенные цифры прогноза: без ИНН, названий контрагентов и назначений платежей.

# ТЗ фронтенда: страницы и кнопки

Vue 3 + Vite + TypeScript. Пользователь — владелец малого бизнеса без финансового образования. Главный вопрос, на который отвечает приложение: **«Хватит ли мне денег и что делать, если нет?»**

Правила для всех экранов:
- пишем без терминов: «денег не хватит», а не «кассовый разрыв»; «скорее всего», а не «P = 0,7»;
- у каждой будущей суммы виден источник: «из истории», «налоги», «вы добавили», «1С», «сценарий»;
- суммы округлены до тысяч («340 тыс. ₽»), даты словами («12 ноября»);
- у каждого экрана три состояния: загрузка, пусто (с кнопкой «что сделать»), ошибка (что случилось и как исправить);
- вёрстка работает от 375 px (телефон).

## Навигация

После входа: слева список компаний (или выпадающий список на телефоне), сверху вкладки компании:

**Прогноз** · **Что если** · **Операции** · **План-факт** · **Источники**

Справа внизу на всех вкладках компании — круглая кнопка **«Спросить»** (ассистент).

---

## 1. Вход `/login`

| Элемент | Что делает |
|---|---|
| Поле «Логин», поле «Пароль» | — |
| Кнопка **«Войти»** | `POST /api/auth/login` → токен в памяти → переход на `/companies` |
| Ошибка | «Неверный логин или пароль» (одинаковая для любой ошибки входа) |

## 2. Мои компании `/companies`

| Элемент | Что делает |
|---|---|
| Карточка компании: название, остаток сейчас, значок риска (зелёный «Денег хватает» / жёлтый «Возможна нехватка» / красный «Не хватит 12 ноября») | клик → Прогноз компании |
| Кнопка **«Загрузить выписку»** (и зона перетаскивания CSV) | `POST /api/companies/import` → после загрузки сразу открыть Прогноз новой компании |
| Пустое состояние | «Загрузите выписку из банка в формате CSV — прогноз появится сразу» + кнопка загрузки |

## 3. Прогноз `/companies/:id` — главный экран

Один запрос `GET /api/companies/:id/dashboard` отдаёт всё для экрана.

**Сверху вниз:**

1. **Ответ одной фразой** — крупно: «Денег хватит до 12 ноября: дальше вероятно не хватит 340 тыс. ₽» или «На ближайшие 30 рабочих дней денег хватает». Под ним мелко: «Сейчас на счёте 1,2 млн ₽ · данные выписки на 30 сентября». Если история короткая — плашка «Мало истории, прогноз приблизительный».
2. **График остатка:** серая линия — факт за 90 дней; синяя линия — прогноз; светлая полоса вокруг — «обычный разброс»; красная пунктирная линия — порог (0 ₽ или неснижаемый остаток); дни ниже порога подсвечены красным.
   - наведение / тап на день → подсказка: остаток, вероятность нехватки, события этого дня;
   - переключатель **30 / 60 / 90 дней** → `GET /forecast?horizon=`.
3. **Предупреждения** — карточка на каждый эпизод (если их нет — зелёная плашка «Нехватки не видно»):
   - заголовок: «12 ноября не хватит 340 тыс. ₽», уровень словами («почти наверняка / вероятно / возможно») и цветом;
   - «Почему»: 2–3 главных платежа (зарплата 120 тыс. ₽, ЕНП 60 тыс. ₽) с бейджем источника;
   - кнопки действий (из `actions`):
     - **«Перенести платёж»** — открывает форму события с этим платежом, чтобы сдвинуть дату;
     - **«Напомнить клиенту»** — копирует готовый текст напоминания в буфер;
     - **«Подключить овердрафт»** — заглушка-переход в «приложение банка» (на демо — модалка «Заявка на 374 тыс. ₽ отправлена»).
4. **Ближайшие события** — список по датам: дата, что, сумма (+ зелёным / − красным), бейдж источника, «скорее всего 80%» для неточных.
   - кнопка **«Добавить событие»** → модалка (раздел 4);
   - у событий с бейджем «вы добавили» / «1С» — иконка корзины **«Убрать из прогноза»** → `DELETE /events/:id`.

## 4. Модалка «Добавить событие»

| Поле | Значения |
|---|---|
| Что произойдёт | переключатель **Деньги придут** / **Деньги уйдут** |
| Сумма, ₽ | число > 0 |
| Когда | дата (только будущие) |
| Что это | текст, например «Оплата от ООО Ромашка» |
| Тип | Счёт клиенту / Счёт поставщика / Налог / Другое |
| Насколько уверены | **Точно** / **Скорее всего** / **Не уверен** (по умолчанию «Скорее всего») |

Кнопки: **«Добавить в прогноз»** → `POST /api/companies/:id/events` с заголовком `Idempotency-Key` (uuid на открытие формы — двойной клик не создаст два события) → закрыть, перезапросить dashboard, тост «Событие добавлено — прогноз пересчитан» и на 3 секунды показать, как сдвинулась линия. **«Отмена»**.

## 5. Что если `/companies/:id/scenarios`

Слева — настройки, справа — результат.

| Настройка | Элемент |
|---|---|
| Крупный клиент заплатит позже | выпадающий список топ-клиентов (из `top_clients` дашборда, с долей «28% поступлений») + «на сколько недель» 1–8 |
| Выручка упадёт | слайдер 0–50 % |
| Внеплановый расход | дата + сумма + название («Ремонт оборудования»), можно несколько — кнопка **«+ ещё расход»** |
| Вырастут постоянные расходы | слайдер 0–50 % (аренда, закупки, коммуналка) |

Кнопки: **«Посчитать»** → `POST /api/companies/:id/scenarios`; **«Сбросить»**.

Результат: один график — две линии «как сейчас» и «если так случится»; под ним карточка разницы: «Нехватка начнётся 3 ноября вместо 12 ноября, не хватит ещё 200 тыс. ₽» или «Даже в этом случае денег хватит». Готовые кнопки-пресеты сверху: **«Клиент задержит оплату на 3 недели»**, **«Выручка −20%»**.

## 6. Операции `/companies/:id/operations`

Таблица: дата · контрагент · назначение (обрезанное, полный текст при наведении) · сумма · категория (бейдж) · как определена (правило / по контрагенту / модель / вы).

- фильтр по категории (`GET /meta/categories`), поиск по контрагенту, пагинация 100 строк → `GET /operations?limit&offset&category`;
- клик по бейджу категории → выпадающий список категорий + галочка **«Применить ко всем операциям этого контрагента»** (по умолчанию включена) → `PATCH /api/operations/:id/category` → тост «Категория изменена у 14 операций, прогноз обновлён»;
- операции-дубли и операции после пропуска в выписке показаны серым с подсказкой «дубль выгрузки — не учитывается».

## 7. План-факт `/companies/:id/plan-fact`

- таблица ожидаемых событий, срок которых наступил: что ждали · когда · сколько · статус (**Пришло** ✓ / **Частично** / **Не пришло** ✗ / **Ждём**) · сколько пришло фактически → `GET /plan-fact`;
- график по неделям: план и факт столбиками рядом, неделя с отклонением > 20% подсвечена;
- кнопка **«Загрузить новую выписку»** → `POST /companies/:id/statements` → перезапрос план-факта. На демо: загружаем «следующую неделю» и показываем, что обещанный платёж не пришёл → появилось предупреждение.

## 8. Источники `/companies/:id/sources`

Карточки — «откуда приложение знает о ваших деньгах»:

| Карточка | Содержимое | Кнопки |
|---|---|---|
| **Банковская выписка** | дата последней загрузки, сколько операций; качество: «найдено 2 дубля — не учитываем», «пропуск 8 дней в марте» | **«Загрузить выписку»** |
| **1С: счета** | последняя синхронизация, сколько неоплаченных счетов подтянуто | **«Синхронизировать»** → `POST /sync/1c`; при ошибке: «1С сейчас недоступна, прогноз построен по выписке» |
| **ФНС: проверка контрагентов** | список клиентов с риском («в ликвидации», «долг перед налоговой») — их оплаты считаются менее вероятными | **«Проверить контрагентов»** → `POST /sync/fns` |
| **Налоги** | режим налогообложения (УСН / ОСНО / ЕСХН), ближайшие налоговые даты | выбор режима → `PATCH /companies/:id` |
| **Ваши события** | список добавленных вручную | **«Убрать»** у каждого |
| **Настройки** | название, отрасль, «Неснижаемый остаток» — сумма, ниже которой предупреждать | **«Сохранить»** → `PATCH /companies/:id` |

## 9. Ассистент (боковая панель по кнопке «Спросить»)

- поле вопроса + подсказки-чипы: **«Хватит ли денег до зарплаты?»**, **«Почему не хватит 12 ноября?»**, **«Что будет, если клиент заплатит позже?»**;
- **«Отправить»** → `POST /assistant/ask`;
- под ответом мелко: «Ответ составлен по шаблону» или «Ответ сгенерирован моделью, цифры — из прогноза».

## Сценарий демо (3–5 минут), под который делаем экраны

1. Загрузить выписку → сразу Прогноз: «Денег хватит до 12 ноября».
2. Открыть предупреждение: почему (зарплата + ЕНП), что делать.
3. Добавить событие «Клиент обещал 300 000 ₽ 20-го» → линия поднялась, предупреждение исчезло.
4. Что если: «клиент задержит на 3 недели» → нехватка вернулась, на графике две линии.
5. Источники: синхронизировать 1С → подтянулись счета; проверить контрагентов → у одного клиента риск.
6. План-факт: загрузить следующую неделю → обещанный платёж не пришёл → предупреждение.

## Порядок работ фронтенда

1. Вход, список компаний, загрузка выписки.
2. Прогноз: фраза, график, предупреждения, ближайшие события.
3. Модалка «Добавить событие».
4. Что если.
5. Операции с правкой категории.
6. Источники и настройки.
7. План-факт.
8. Ассистент.

Пункты 1–3 — обязательный минимум кейса («интерфейс: график остатка и список предупреждений»), без них остальное не засчитают.

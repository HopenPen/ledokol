# ТЗ разработчику: что уже есть и что делать дальше

Состояние на 24.10.2026. Скелет работает целиком: выписка → категории → прогноз → разрывы → API → интерфейс на Vue. Проверено: 31 автотест зелёный, пакетный прогноз по 150 компаниям датасета проходит, демо открывается в браузере, сценарий «что если» считает.

Задачи ниже идут по приоритету. Сначала — то, без чего жюри не засчитает минимум, потом то, что даёт баллы.

## 1. Как устроен код (5 минут на чтение)

```
cashflow-app/
├── backend/                 Python 3.11, FastAPI, окружение через uv
│   ├── app/domain/          ВСЯ бизнес-логика: чистые функции на pandas, без HTTP и БД
│   │   ├── ingest.py        чтение CSV кейса, дубли через сверку остатка, «дыры» в выписке
│   │   ├── categorize.py    категории: правила → история контрагента → ML (TF-IDF + логрег)
│   │   ├── categories.py    справочник категорий и их роль в прогнозе
│   │   ├── recurring.py     регулярные платежи (аренда, зарплата аванс+расчёт, кредиты…)
│   │   ├── taxes.py         ЕНП по налоговому календарю
│   │   ├── tax_rules.py     все налоговые сроки РФ 2026 (УСН, НДС 22%, НДФЛ 28/5, взносы ИП)
│   │   ├── forecast.py      гибридный прогноз: события + выручка по дням недели + остаток, Монте-Карло
│   │   ├── risk.py          разрывы: дата, сумма, вероятность, причины, действия, тексты
│   │   ├── scenarios.py     «что если» без переобучения модели
│   │   ├── planfact.py      сопоставление ожидаемого и фактического
│   │   └── ml_flow.py       CatBoost — экспериментальный 4-й подход (не подключён)
│   ├── app/services/        склейка домена с БД: импорт выписки, кеш модели, события, интеграции
│   ├── app/api/             FastAPI: схемы (extra=forbid), проверка владения, роуты
│   ├── app/integrations/    HTTP-клиенты 1С и ФНС с повторами и таймаутами
│   ├── app/llm/             необязательный ассистент через любой OpenAI-совместимый API
│   ├── app/backtest/        rolling-origin бэктест и метрики
│   ├── app/batch/           задел под Spark для всего портфеля банка
│   ├── app/mcp_server.py    задел: MCP-сервер поверх прогноза
│   ├── app/cli.py           predict / backtest / seed-demo / train-classifier
│   └── tests/               pytest: домен, API на реальной SQLite, логи, интеграции
├── frontend/                Vue 3 + Vite + TypeScript, графики на ECharts
├── mocks/                   сервисы-имитаторы 1С (OData) и ФНС (REST) — отдельные HTTP-сервисы
└── docs/                    ТЗ, экраны, нормативка
```

Главное правило: формулы и правила — только в `app/domain`. API, CLI и бэктест вызывают один и тот же код, поэтому то, что показываем на демо, ровно то, что измеряем.

## 2. Текущие метрики (бэктест, 4 отсечки на компанию, горизонт 30 рабочих дней)

| Что | dev (114 компаний) | holdout (29 компаний) | Цель из ТЗ |
|---|---|---|---|
| Разрывы: полнота (recall) | 0,68 | 0,55 | ≥ 0,7 |
| Разрывы: точность (precision) | 0,55 | 0,58 | ≥ 0,5 |
| Заблаговременность, медиана | 13 раб. дней | 9 раб. дней | ≥ 10 |
| Остаток (операционный), MASE к наивному, h=5 / 10 | 0,92 / 0,97 | 0,93 / 0,94 | < 1 |
| Остаток (операционный), MASE, h=20 / 30 | 1,03 / 1,06 | 1,06 / 1,17 | < 1 |
| Покрытие интервала P10–P90 | 0,73 | 0,69 | ≈ 0,8 |

Вывод: детектор разрывов почти у цели, точность остатка на дальнем горизонте и ширину интервала нужно доработать (задачи 3.1–3.3).

«Операционный» остаток — это факт без денег владельца и переводов между своими счетами. Модель их сознательно не прогнозирует: это реакция на разрыв, а не план. На слайде это надо объяснить одной фразой.

## 4. Правила для всех, кто пишет код

1. Логика — в `app/domain`, сервисы — только склейка, роуты — только HTTP.
2. Никаких констант под конкретные компании датасета: проверка будет на контрольном датасете.
3. В логи — только id и коды событий. Никаких ИНН, наименований, назначений, сумм с контрагентом.
4. Любая новая мутация — подумать, что будет при повторе запроса (идемпотентность).
5. Комментарии и тексты интерфейса — по-русски, комментарий объясняет «почему», а не «что».
6. Перед мержем: `uv run pytest` зелёный, `npm run build` без ошибок.

# MCP поверх прогноза

Локальный stdio-сервер предназначен для ассистента банка. Он не является публичным HTTP API:
все вызовы выполняются от одного пользователя, заданного оператором через `CASHFLOW_MCP_USER`.
Доступ к другим компаниям этого пользователя не расширяется параметрами инструмента.
Внешний общий сервер потребует отдельной аутентификации каждого клиента.

## Запуск

В `backend/` установите существующий optional extra: `uv sync --extra ml --extra mcp`.
Параметры базы берутся из обычного окружения backend. Например, в PowerShell:

```powershell
$env:CASHFLOW_MCP_USER = 'demo'
uv run --no-sync python -m app.mcp_server
```

SDK 2.x использует `MCPServer`; для SDK 1.x сохранён импорт `FastMCP`. Зависимости не добавлялись.

## Инструменты

- `list_companies()` — внешние id компаний текущего пользователя.
- `forecast_summary(company)` — обезличенная сводка через существующий `build_context`.
- `list_clients(company)` — до пяти крупнейших клиентов: только `client_ref` и доля поступлений.
  Имя, ИНН и исходный ключ контрагента не передаются. Ссылка действует в пределах компании;
  если состав крупнейших клиентов изменился, список нужно запросить заново.
- `what_if(company, revenue_drop_pct=0, fixed_cost_increase_pct=0, client_delay_weeks=0, client_ref=None)` —
  сравнение прогноза до и после сценария. Падение выручки от 0 до 90%, рост расходов от 0 до 100%.
  Для задержки выберите ссылку из `list_clients` и целое число недель от 2 до 4.
  Без задержки параметры клиента не передаются. Неизвестный клиент и выход за пределы дают ошибку,
  значения не обрезаются молча.

Пример последовательности: `list_companies` → `list_clients` → `what_if` с выбранным `client_ref`
и `client_delay_weeks=3`. Параметры задержки, падения выручки и роста расходов комбинируются.

`what_if` возвращает JSON с прежними полями `headline`, `gaps` и новыми `before`, `after`.
Каждая сводка содержит дату первого разрыва `first_gap_date`, его сумму `shortfall`, вероятность
`probability` и число разрывов `gaps`. Без разрыва дата равна `null`, сумма и вероятность — нулю.
Суммы округлены до тысяч, вероятности — до двух знаков, как в контексте для LLM.

Ни один инструмент не сохраняет события или снимки прогнозов. Кэш модели в памяти может прогреться.
Обычный прогноз через HTTP по-прежнему сохраняет официальный снимок для план-факта.

## Проверка

После установки extra: `uv run --no-sync pytest tests/test_mcp_server.py tests/test_mcp_stdio.py`.
Проверяются регистрация инструментов в SDK, отсутствие SQL-записей, сохранение снимков обычным
путём, владение компаниями, входные ограничения, выбор клиента и обезличенное сравнение разрывов.
Без установленного optional extra эти тесты пропускаются.

Проверка stdio запускает отдельный процесс: handshake, обнаружение четырёх инструментов,
read-only аннотации, вызовы и запрет доступа к чужим компаниям.

## Подключение клиента

В конфигурации MCP-клиента укажите абсолютный путь к backend и нужный логин:

```json
{
  "mcpServers": {
    "cashflow": {
      "command": "uv",
      "args": ["--directory", "D:/!finance/catboost-publish/backend", "run", "--extra", "mcp", "--extra", "ml", "python", "-m", "app.mcp_server"],
      "env": {"CASHFLOW_MCP_USER": "demo"}
    }
  }
}
```

База и настройки должны соответствовать выбранному backend. Все четыре инструмента
помечены как read-only. Пример запроса: «Покажи мои компании, затем прогноз разрыва;
сравни его со сценарием падения выручки на 20%».
